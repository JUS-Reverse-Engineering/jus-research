# Ultimate Action table (SELECT, move id 11, anim 0x18)

Generated by `scripts/analysis/ua_table.py build`; do not edit. `python -B scripts/analysis/ua_table.py check` verifies freshness. Machine-readable copy: [ua-table.json](ua-table.json). Static: read from each character's motion table, the shot files and ov6, no emulator. Owner statements on the Ultimate Actions: [OWNER-NOTES.md](../research/moveset-notes/OWNER-NOTES.md#ultimate-actions-owner-2026-10-12).

## Rules

- **Trigger.** The ground reader tests SELECT (0x1000) at 0x0215A7D0 and returns move id 11 = anim 0x18, state 0x0C, with no SP cost. The air reader returns only ids 9 and 10, so an airborne SELECT is not the UA. Every battle prefix has an anim 0x18 row below.
- **Team register.** `ctrl+0xA3` is a per-team byte, -1 at init (0x0215542C). Sub 19 (`store`, 0x021560EC) writes its signed value ev[2]. Sub 20 (`stored_jump`, 0x021560F8) queues a jump to the Marker whose id is the stored value and resets the byte to -1, even when the anim has no such Marker. Only ov6 writes it; the switch and the hit path do not clear it (review.md b3-b5).
- **Op 3 arguments** (case table 0x02157A68, one branch per arg): 2 spawn (shot row ev[4]), 7 invuln (+0xCE, s16 ticks), 9 arm_substitute (decoy index ev[4], signed; the arm lasts 121 ticks, 0x0215A980), 10 status (u16 ev[4..5] indexes the byte table at 0x0217215C, giving the status id the acting fighter receives; 0x02157C5C), 23 hp (s16 ev[4..5]; HP raw = displayed HP x 64), 24 sp (s16 ev[4..5]; SP raw 25600 = one bar). Args 17 and 18 and any other arg are kept raw with grade `lead`.
- **Op 1 sub 3 impulse.** x = ev[2] * 32 (facing-signed), y = ev[3] * -126 (table 0x02172020[3] = 0x0215669C, `mvn r0,#0x7d` at 0x021566F4).
- **Op 3 sub 1** is the end key (0x0215693C): `ends` per anim. The playhead events (sub 0, 1, 2, 3, 4, 18, 19, 20, 23) decode with the mash table's decoders.
- **Spawn rows** are op 3 arg 2 events. The shot row (chr/shot/<prefix>.bin, 32 bytes, art u32 at byte 12) is measured. `kb_recs` is an inferred join (review c4): the art's low byte is an anim id, and `kb_recs` lists the knockback records whose collision track keys that anim (`knockback_table.record_uses`). The join can be ambiguous: several records can match one row (ds_b_01 spawns list [11, 15]), and bc_b_02 row 0 (art 0x00074241) matches none. `has_kb_record` is true when `kb_recs` is non-empty and null only when the row is not in the file.
- **Stores and jumps** are cast-wide: every sub 19 and sub 20 in every anim of the prefix (any member), with `targets` = {Marker id: frame} for every Marker of that anim. The consumers column joins a stored value to the jumps of the same character that list it.

## Open questions

- has_kb_record and kb_recs: the join (art low byte = anim id, review c4) is inferred, not traced to a hitbox. One row can match several records (ds_b_01: [11, 15]), so kb_recs is a candidate list, not a single record.
- Args 17 and 18 have addresses but no traced semantics; they are `lead` rows.
- Stored values are a team register; the stored value persists across character switches (review.md b4) and the consumers listed here are per prefix, so a cross-prefix consume is not joined.
- Owner statements on the Ultimate Actions: [OWNER-NOTES.md](../research/moveset-notes/OWNER-NOTES.md#ultimate-actions-owner-2026-10-12).
