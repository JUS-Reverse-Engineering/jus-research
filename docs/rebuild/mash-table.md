# Mash table: tap-extendable moves for every character

Generated by `scripts/analysis/mash_table.py build`; do not edit. `python -B scripts/analysis/mash_table.py check` verifies freshness. Machine-readable copy:
[mash-table.json](mash-table.json). Static: read from each character's motion table and ov6
disassembly, no emulator.

A mash move is an animation with a NoteTrack event that counts presses of a button in the input
history and branches (ov6 op 0 sub 0 or sub 18). Sub 1 (hold), sub 23 (direction), sub 5
(contact), sub 9 (counter) and sub 14 (deck count) are other input or state branches. `input_conditional`
includes those state branches. Subs 2, 3, 4, 19 and 20 (loop, ground wait, air
wait, store, stored jump) do not read the pad; they are decoded here because they move the same
playhead (see Event kinds).

Names: idx 2 = X, idx 1 = Y (inferred); idx 0 = B and idx 3 = SELECT (the ground move reader maps 0x80 to the B moves and 0x1000 to the Ultimate Action, id 11). A marker is a frame of the anim's `Marker` track. The counter (fn 0x021561A8) bumps on every evaluation of a limited event, pressed or not; the (limit+1)th evaluation is blocked and resets it to 0; a limit of -1 is unlimited and does not bump. Only ov6 writes the byte (obj+0xA2), so every limited event of an anim shares it (Train's two events on 0x21 share one count).

## Press counting

Counter 0x021613C4 over the history updater 0x02161148. The input history is a ring of 16 segments, each a run of an unchanged input word with its stored duration (length - 1), plus the current word and its duration. An edge (the button's edge mask above) counts if its age is at most the window, where age counts only the ticks on which the word stayed unchanged: the raw age minus the number of word changes since the edge. A current word older than the window counts nothing. The history runs continuously across moves, so presses from before the move count. Facing is not a bit of the word: when the fighter faces left the updater swaps the LEFT and RIGHT bits (4 and 8), so a turn is a word change only while a horizontal is held. Directions are held-only bits; the shoulder bits (0x4000, 0x8000) are edge-only. A run's duration rolls over at 600. The updater runs before the check in the same tick. This reproduces all 35 committed Kakashi side Y trials of wmqi2-guard-2026-09-22 (31 distinct tap schedules in `logs/mash_summary.json`) and the historical +4,+12 row. The 15 review cases (14 of those schedules plus the historical row) fit 15 of 15; counting plain edges in the last `window` elapsed ticks fits 11 of 15. A jump queued by an event lands on the next tick, so a loop adds (check - marker + 1) ticks. Sub 0 returns before the counter when [obj+0x78] is 0.

## Event kinds

Op 0 events of these subs are decoded (rows in the JSON; fields in the layout table). All are measured bytes at measured offsets; the meaning is read from the handler code unless marked.

- **loop** (sub 2, 0x021559C0): an unconditional jump to Marker ev[2] through the shared counter with limit ev[3] (-1 = unlimited, no bump). It queues on slot 6 (queue kind 0, `slot_for_kind`).
- **ground_wait** (sub 3, 0x02155CAC): arms slot 0 with queue kind 2 and Marker ev[2]; ev[2] = -1 (`disarm`) empties it. Each callback polls slot 0 first (slot loop 0x02155700); handler 0x021562E8 returns 1 iff `[[obj+0x7C]+0x10]+0x78` bit 0x02 (grounded). Grounded: jump to the armed marker from any frame, slot 0 empties, and the slot-6 jump queued the tick before is dropped. Not grounded: the queued slot-6 jump applies. Eve 0x2c: arm Marker 9 (f66) at f62, loop to Marker 8 (f62) at f65, disarm at f66.
- **air_wait** (sub 4, 0x02155D00): the same slot 0 with queue kind 4, whose handler (0x02156358) returns 1 iff NOT grounded. Decoded, not modeled.
- **counter_wait** (sub 9, 0x02155DB8): STATIC: queues kind 9 in slot 2 with signed Marker ev[2]; -1 disarms. Poll 0x021564E8 tests ColPrm+0x40 & 0x20000. Kenshin rk_b_01 anim 0x2a arms marker 1 at f6, targets f47 and disarms at f47. The rec-7 counter box is active f6-22; the armed wait is not an invulnerability window. Decoded data only, not modeled in mash_path.py. See p230.
- **contact_wait** (sub 5, 0x02155D3C): STATIC: arms a marker jump on contact; marker -1 disarms. `marker_frame` is the resolved target, null for disarm or an absent marker.
- **deck_count_branch** (sub 14, 0x02155E90): STATIC: query 0x42 selects the first matching `tiers` entry in descending `min_count` order. Each entry has `marker` and resolved `frame`; no matching threshold falls through. Both branch decoders come from `anim_events.py`. See [the static branch analysis](../research/2026-10-15-taikoubou-6kx-branches.md). UNMEASURED: live contact conditions and deck-count behavior. Neither branch is modeled in `mash_path.py`.
- **hold_release** (sub 1 with no hold tier set, 0x02155B04): button ev[2], default Marker ev[4]. Static trace (unverified live): a level poll from the tick after creation that fires on the first tick the button is not down (0x02161440). Tiered sub 1 events keep the kind `hold_tiers` (a lead).
- **store** (sub 19, 0x021560EC): writes ev[2] (signed) to ctrl+0xA3. **stored_jump** (sub 20, 0x021560F8): if ctrl+0xA3 is not -1, queue a kind-0 jump to that Marker and reset it to -1 (also when the anim lacks the marker). The event bytes are recorded here only; `targets` lists every marker of the anim, and the join to stored values belongs to the UA scanner. `mash_path.simulate(stored=v)` models the read (a MashEvent of kind `stored_jump` with `targets`): it consumes `v` on its first pass and jumps if `v` is a target.
- **ends** (op 3 sub 1, 0x0215693C): per anim, the frames of end keys; it sets ctrl+0x90 |= 0x10000000.

## Reference model

`scripts/analysis/mash_path.py` is a deterministic simulator of the rules above: from an anim's mash events (this table), its frame count and an input word per tick it returns the playhead frame per elapsed tick, the jumps taken, the idle tick, and the tick on which each box key frame is entered with its contact tick. `scripts/tests/test_mash_path.py` pins it against the Kakashi trials, Eve k4/k5 (with the landing) and Train's shared counter.

- Idle: `idle_tick = M_IDLE + (elapsed - playhead)` with `M_IDLE = frames + 3` for a grounded move. Each loop pushes idle later (Eve k4: 42, 55, 68).
- Per tick: if slot 0 is armed and `t >= grounded_from`, the playhead goes to the armed frame, slot 0 empties and a pending slot-6 jump is dropped; otherwise the pending jump applies. Events run, then the playhead advances by 1 (a jump queued on tick t lands on t + 1).
- **TUNING, contact on a jump landing** (5 of 5 cases): a box key entered on tick t touches on t + 1, except that when the jump target is not check + 1, the box keyed at the target frame touches with delay 0. Eve k4 contacts at +12, +16, +20, +24, +29, +33, +37, +42, +46, +52 (24 and 37 are the landings); k5 unmashed 276 at +0; k5's adjacent jumps f19 to f20 and f25 to f26 stay +1.
- **Jump landing (static RE, why the delay is 0)**: a jump queued on tick t lands on tick t + 1. NoteTrack (task key 0x86000, callback 0x02155688) applies the queued jump through the motion controller's vtable[0xEC] (0x0201BFA0), which reaches setFrame (0x0201F9B8). setFrame returns early when the target equals the current frame; otherwise it stores the frame and dispatches every frame-keyed track through vtable[0xCC] (0x0201F734) at once, so the hit type (CollisionType listener 0x0207A2F4), enable, rect, hurt box and sprite all change before the collision driver (key 0x9E000, 0x0207F480) runs in the same tick: contact delay 0. A normal advance (Step 0x0201BDEC) only arms a pending-dispatch flag; Tick (0x0201C118) dispatches it later, after collision, so the box is first seen one tick later: +1. An adjacent jump (target = check + 1) is a normal advance (+1). The Tick-after-collision placement is inferred, not found by a caller search; the rule fits the 5 cases above.
- **TUNING, history scope**: the ring is modeled as one history per fighter that runs across moves. Whether the native history is per fighter or per team is not tested (Kakashi trials ran one active fighter).
- **Ground wait (Eve k5 up X, Train air Y)**: the hop's 2 to 5 tick idle residual is the sub 3 / sub 2 pair in the anim (Event kinds). `simulate(..., grounded_from=L + 1)` over `events_from_row(row, waits=True)` reproduces all 8 measured idles for 2 to 9 hits (landing ticks 31, 39, 45, 52, 58, 64, 70, 76 give idles 53, 61, 67, 74, 80, 86, 92, 98; E3b capture, docs/research/feel-captures/2026-10-12-eve-mash/compare.json). The landing tick is an input, not derived: the model has no physics. With no landing given the wait is not modeled (the arms and the wait loop are skipped), which gives 51 unmashed and 81 all-true, the old numbers. Not reproduced: air wait (sub 4) is decoded but not simulated; a sub 2 or sub 3 whose marker is absent from the anim has no frame and is left out of the model; the landing of Train air Y needs its own capture.
- **End keys**: a move ends 2 ticks after the playhead reaches the first end key (op 3 sub 1, `ends` per anim), else at frames + 3. Train side Y (key f49) idles at 51, up Y (f43) at 45, air Y (f58) at 60, all measured; `mash_path.end_idle` computes it. The five measured idles behind the 5 of 5 grade note: Train side Y 51 = 49+2, up Y 45 = 43+2, air Y 60 = 58+2, Yusuke side Y 53 = 51+2, Kakashi UA 60 = (34 + 24 loop frames) + 2.

Grades: bytes, frames, offsets and marker frames are measured; what a field means is inferred from
the handler code; sub 1 and sub 23 decodes are leads. See `grade_notes` in the JSON.

## Open questions

- Franky Y, Vegeta X and Goku Kaio Ken are guide-tagged mash but have no NoteTrack input event (Franky's Y grows with the stored UA value, a stored jump, not a mash event).
- The press counter 0x021613C4 also has two non-NoteTrack callers (functions 0x02158B20 and 0x0215D564), so code-driven mash isn't covered by this scan.
- Anims 0x2f-0x31 carry mash events but have no move label.
- Move labels come from the shared ov6 move table and are measured only for Kakashi and Yusuke (anim-timing.json). Yusuke side Y plays 0x28, not the table's 0x21, so other fighters may be remapped too. Ids 13 and 14 take their anim from a per-fighter byte that wasn't read.
